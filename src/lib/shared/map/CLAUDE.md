# Map: what it draws (both apps)

This folder is shared with the native app, so a decision about what the map draws is made once here. The web map's own notes are in `src/lib/map/CLAUDE.md`.

## Styling

- `style.ts` is the **single source of truth** for colours, widths and opacities (`COLORS`, `WIDTHS`, `CIRCLES`, `LABELS`, `OPACITIES`). Route colour = visit status × line_class; width is one z4→z7 interpolate.
- **Visit status is the map owner's rides, by feature id** (`routeRides.ts`): the route tile is Martin's and the same for everyone. `indexRides` sorts them into whole, partial and closed id lists. `getUserRouteColorExpression` is a `match` on `["id"]` over the first two, `getUserRouteSortKeyExpression` draws ridden over unridden (`line-sort-key`), and `closedRoutesFilter` keeps the third. A `match` may not have an empty label list, so an empty status is left out. `userRouteLayerConfigs` and `createUserMapLayers` take the rides; `createUserMapLayers(…, null)` builds the route lines and click buffer hidden. Tested in `tests/routeRides.test.ts`. An invisible wide `railway_routes_click` layer (every shown usage type, `clickBufferFilter`) gives touch hit areas.
- Route layer ids come from `layers.ts` (`routeLineLayerId`, `REGULAR_ROUTE_LAYER_ID`, `ROUTE_LINE_LAYERS`, `ROUTE_CLICK_LAYER_ID`). Never write them out anywhere else.
- **The colour expression: no `["all", ...]` in data-driven paint.** MapLibre Native's React binding crashes (`std::bad_alloc`) converting a `case` with an `all` condition beside another branch. Write nested single-condition `case`s and use `match` for a value fan-out (`utils/userRouteStyling.ts`, `lineClassColorExpression`). The admin map follows the same rule, though only the web draws it.
- **No constant filter (`false`, `true`) on a layer**: the iOS binding turns it into a predicate like `0 == 1`, which MapLibre Native refuses ("Invalid predicate"). Match nothing with a comparison no feature passes (`usage_type == -1`, as `usageTypeFilter([])` and `coverageFilter` do).
- **Scenic lines** (`createScenicLinesLayer`): a translucent blue band under the route lines (deep blue light, sky blue dark, `scenicLineColor`; the admin map too), from `scenic_lines_tile` (simplified to 1.5 pixels and rounded off with Chaikin, so the band doesn't copy every kink of the track). On the user map the band is off by default behind the "Scenic lines" switch, which exists only where `hasScenicHighlight`, and it follows the country filter through `scenicLinesFilter`.
- **The country filter is a layer filter, in both apps** (`countryFilter`, through `userRoutesFilter` on the route lines and click buffer, `scenicLinesFilter`, the coverage layers), so the route tile's URL never carries the ticked countries: a toggle refetches nothing, and the URL is the same for everyone, so Martin caches one copy. Highlights don't take it, so a journey, trip or plan shows whole. `railway_routes_tile` still accepts `selected_countries` for native builds from before the move.
- Each usage type has its own line layer (`railway_routes`, `_heritage` dotted, `_special` dashed), because `line-dasharray` isn't data-driven.
- **Closed routes** are filtered per route layer on the client, since the tile carries no rides: `createRouteLineLayer`'s `routesFilter` narrows the usage type (`routeLineFilter`), fed by `closedRoutesFilter` on the user map and the admin's own filter there. `OPEN_ROUTES_FILTER` is the one place the `closed` property is read. The user configs carry the switch-off default, so nothing flashes. An anonymous visitor's map lets every logged route through until the statuses load (`provisionalRides`), then the closed ones among them. The route line and the ridden stretches over it are faded alike (`closedRouteOpacityExpression`). The popup's first badge says "Closed" (`routeBadges`).
- Dark mode: the layers chosen to stand out against the basemap follow the scheme. That means stations (`COLORS.stationsDark`) and the user map's visit states (`routeColors(theme)` through `userRouteLayerConfigs(theme)`: three hues, with highspeed lighter rather than darker). The admin map keeps the light palette. Popup badges carry a `dark` pair.
- Zoom ranges: `ZOOM_RANGES` in `zoomRanges.ts`. Its header lists what else must match.
- **The route tile carries no text and no rides**, only what the layers style and filter by. A popup's or a click's names, note, tags, link and length are read by `track_id`: on the web from `routeDetails.ts` (one `GET /api/route-details` per region, preloaded as the interactions attach; a popup opened before it arrives says "Loading…" and is rebuilt through `hover.refresh`), in the native app from `POST /api/v1/routes/metadata` on the tap. Don't add text back to `railway_routes_tile`: it was over half of a low-zoom tile's bytes and time.
- Tile URL templates (`tileSources.ts`) take the tile host as an argument. Query strings are built by hand, for RN. Martin caches the versioned route tile under the raw query string, so its URL carries `v` alone. `railwayRoutesTileUrl` with a `version` names the cached source (`railway_routes_tile_versioned`), without one the uncached source. Tested in `tests/tileSources.test.ts`.

## Basemap (`basemap.ts`)

- OpenFreeMap `liberty` (`dark` in dark mode). It is vector so that the labels can be rewritten to Latin script (`latinizeLabels`: `coalesce(name:latin, name_en, name)` on layers that _read_ a name). On top of it, each explained in the file: the fade layer, admin_level 2 borders redrawn above the fade, in dark mode the place names lifted above the fade and restyled (`restylePlaceLabelsDark`, split out as `labels` by `transformBasemapLayers`; both apps take the stack from `basemapLayers`, tested in `tests/basemap.test.ts`), POI layers dropped (`dropPoiLayers`), missing icons backfilled (web: `src/lib/map/missingIcons.ts`), buildings flattened (`flattenBuildings`). Park label points are filtered out of `park_outline` (`filterPointsFromParkOutlines`). Liberty's `park_outline` is an unfiltered `line` layer over a source-layer that also carries a label point per park, which MapLibre Native logs as "Invalid geometry in line layer".
- The style is fetched **before** the map is created (`loadBasemapStyle`, memoised). It resolves null on failure or after a 6s timeout, which falls back to OSM raster. Never call `setStyle` later, because it discards our layers. Never mutate the memoised layer objects.
- **Station labels are ours** (`createStationLabelsLayer`, `LABELS.station`, styled after openstreetmap-carto). Keep the halo translucent.
- **`text-font` must name exactly one font.** MapLibre joins the array into one glyph URL, which OpenFreeMap 404s, and the text silently falls back to a system font. Text also needs `glyphs`; the raster fallback declares `GLYPHS_URL`.

## Highlights and overlays

- Selection colours: Route Logger orange `#ff6b35`, Journey Planner gold `#FFD700`, My Trips orange.
- A highlight set is split by usage type (`highlightVariants`, `highlightLayers.ts`) and reuses the base layer's width and dash. The non-regular variants get a translucent solid casing underneath. The casings are in `HIGHLIGHT_LAYER_IDS`, which gives Heritage/Special routes their hit area. Highlights ignore the layer switches.
- Routes covered only in part get their overlay from a per-set `<baseId>_partial` GeoJSON source rather than the tile (`PartialRouteGeometry`, carrying `usage_type`). That covers the planner result, the Route Logger selection's partial routes, and an opened journey's or trip's logged stretches (a trip's are the union of its journeys'). The source is split by usage type with the same widths, dashes and casings (`createPartialHighlightLayers`). Empty it with `setData`, never remove it. A stretch carries only the route id, so a tap is hit-tested through `PARTIAL_HIGHLIGHT_LAYER_IDS` and the route is read from the tile.
- **Ridden stretches** (`coverageLayer.ts`) are drawn green over the route from a `logged_coverage` GeoJSON source: one layer per usage type, moved before `stations`, repeating the route layers' usage and country filters.
- **Never `simplify` an overlay**: the stretches are drawn over the route's own line. The line tiles are simplified only by one tile unit (see `database/CLAUDE.md`).

## Layer prefs (`layerPrefs.ts`)

The stored form and how it resolves per region. Heritage, closed and scenic are one value for every region; the Special and Regular switches are stored per region, and `showRegular` exists only where `hasOrdinaryNonRegular`. `switchableUsageTypes` decides which switches a region has. The Special layer's default follows `ordinaryUsageTypes`.
